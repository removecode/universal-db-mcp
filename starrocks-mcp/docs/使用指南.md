# starrocks-mcp 使用指南

本文档面向 **使用者与运维人员**，介绍如何安装、配置、接入客户端并日常使用。接口字段详见 [api.md](api.md)；架构与安全设计详见 [项目说明.md](项目说明.md)。

---

## 1. 使用前准备

### 1.1 环境要求

| 项目 | 要求 |
|------|------|
| Python | 3.10+（推荐 3.11） |
| 网络 | 运行 MCP 服务的机器能访问 StarRocks（MySQL 协议端口） |
| StarRocks 账号 | 建议准备只读、读写两个账号（见下文） |

### 1.2 你会拿到什么

启动成功后，服务提供：

| 端点 | 鉴权 | 用途 |
|------|------|------|
| `http://<host>:8080/mcp` | 需要 apikey | MCP Streamable HTTP（Cursor 等） |
| `http://<host>:8080/sse` | 需要 apikey | MCP SSE（OpenClaw 等默认传输） |
| `http://<host>:8080/healthz` | 不需要 | 健康检查 |
| `http://<host>:8080/metrics` | 不需要 | Prometheus 指标 |

## 2. 快速开始（Mock 模式，无需真实库）

适合本地开发、演示、跑测试。

```bash
cd starrocks-mcp
pip install -e ".[dev]"

cp config/settings.example.yaml config/settings.yaml
cp config/apikeys.example.yaml config/apikeys.yaml
```

确认 `config/settings.yaml` 中：

```yaml
database:
  driver: mock
```

生成测试 apikey 哈希并写入 `config/apikeys.yaml`：

```bash
python -c "import hashlib; print('sha256:' + hashlib.sha256(b'my-test-key').hexdigest())"
```

启动：

```bash
python -m starrocks_mcp.main --config config/settings.yaml
```

验证：

```bash
curl -s http://127.0.0.1:8080/healthz
# 应返回 "status":"ok" 且 "mode":"mock"
```

## 3. 连接真实 StarRocks

### 3.1 修改 settings.yaml

```yaml
database:
  driver: pymysql
  host: 10.58.16.10
  port: 5744
  charset: utf8
  read_account:
    user: reader
    password: ${STARROCKS_READ_PASSWORD}
  write_account:
    user: writer
    password: ${STARROCKS_WRITE_PASSWORD}
```

设置环境变量（不要把密码写进仓库）：

```bash
# Linux / macOS
export STARROCKS_READ_PASSWORD='your-read-password'
export STARROCKS_WRITE_PASSWORD='your-write-password'
```

```powershell
# Windows PowerShell
$env:STARROCKS_READ_PASSWORD = 'your-read-password'
$env:STARROCKS_WRITE_PASSWORD = 'your-write-password'
```

### 3.2 StarRocks 侧建议授权

```sql
-- 只读账号
CREATE USER 'reader'@'%' IDENTIFIED BY 'xxx';
GRANT SELECT ON *.* TO 'reader'@'%';

-- 读写账号（DDL 不要授权，服务端也会拦截）
CREATE USER 'writer'@'%' IDENTIFIED BY 'yyy';
GRANT SELECT, INSERT, UPDATE, DELETE ON *.* TO 'writer'@'%';
```

若暂时只有只读账号，可将 `read_account` 与 `write_account` 配成同一账号；此时 `readwrite` 角色的写操作会在数据库侧被拒绝。

### 3.3 启动并验证

```bash
python -m starrocks_mcp.main --config config/settings.yaml --log-level INFO
```

```bash
curl -s http://127.0.0.1:8080/healthz
# driver 为 pymysql、mode 为 live 时表示已连真实库
```

连不上时 `/healthz` 返回 **503**，`message` 字段会说明原因。

## 4. 配置 apikey 与用户

编辑 `config/apikeys.yaml`（**只存哈希，不存明文**）：

```yaml
users:
  alice:
    api_key: "sha256:<alice-key 的哈希>"
    id: bi-team-readonly
    role: read
    scope:
      - catalog: paimon
        database: csc

  bob:
    api_key: "sha256:<bob-key 的哈希>"
    id: etl-job
    role: readwrite
    scope: null
```

生成哈希：

```bash
python -c "import hashlib,sys; print('sha256:'+hashlib.sha256(sys.argv[1].encode()).hexdigest())" "your-raw-api-key"
```

| 字段 | 说明 |
|------|------|
| `role` | `read`（只查）或 `readwrite`（可查可写） |
| `scope` | 限制可访问的 catalog/database；`null` 表示不限制 |
| `id` | apikey 标识，用于 Prometheus 指标标签 |

把 **明文 apikey** 发给客户端使用者；服务端配置文件里永远不要出现明文。

### 本地开发账号

使用 `config/settings.local.yaml` + `config/apikeys.local.yaml` 时，内置：

| 用户 | 明文 apikey | 权限 |
|------|-------------|------|
| alice | `alice-local-dev-key` | 只读，`paimon.csc` |
| bob | `bob-local-dev-key` | 读写，不限范围 |

```bash
python -m starrocks_mcp.main --config config/settings.local.yaml
```

## 5. 在 Cursor 中接入

### 5.1 确保服务已启动

本机终端运行 MCP 服务后，应看到类似：

```text
Uvicorn running on http://127.0.0.1:8080
```

### 5.2 配置 MCP

打开 Cursor Settings → MCP，或编辑配置文件：

- 全局：`~/.cursor/mcp.json`（Windows：`C:\Users\<你>\.cursor\mcp.json`）
- 项目级：`.cursor/mcp.json`

```json
{
  "mcpServers": {
    "starrocks": {
      "url": "http://127.0.0.1:8080/mcp",
      "headers": {
        "X-API-Key": "alice-local-dev-key"
      }
    }
  }
}
```

要点：

- URL **必须带** `/mcp`
- Header 名为 `X-API-Key`（也支持 `Authorization: Bearer <key>`）
- 使用 **Streamable HTTP**（`url` + `headers`），不要用 stdio / mcp-remote 桥接

保存后在 MCP 面板刷新，状态应变为已连接。

### 5.3 在对话中试用

可让 Agent 依次调用：

1. `get_connection_status` — 确认数据库可用
2. `get_database_info_tool` — 浏览表结构
3. `execute_sql` — 执行查询，例如：

```sql
select * from paimon.csc.ods_csc_log_audit
where app_id='hids-identify-result-storage-svc'
  and year=2026 and month=202606 and day=20260610
limit 2
```

更多 Cursor 说明见 [local-cursor.md](local-cursor.md)。

### 5.4 在 OpenClaw 中接入（SSE）

服务同时提供 `/sse` 端点，兼容 OpenClaw 等默认使用 SSE 传输的客户端：

```json
{
  "mcp": {
    "servers": {
      "starrocks": {
        "url": "http://<host>:8080/sse",
        "headers": {
          "X-API-Key": "your-api-key"
        },
        "requestTimeoutMs": 120000
      }
    }
  }
}
```

要点：

- URL **必须带** `/sse`（可不写 `transport`，OpenClaw 默认即为 SSE）
- 若客户端支持 Streamable HTTP，也可改用 `http://<host>:8080/mcp` 并设置 `transport: "streamable-http"`

## 6. 用 Python SDK 调用

```python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

async def main():
    headers = {"X-API-Key": "your-api-key"}
    async with streamablehttp_client(
        "http://127.0.0.1:8080/mcp", headers=headers
    ) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()

            # 检查连通性
            status = await session.call_tool("get_connection_status", {})
            print(status.content[0].text)

            # 浏览结构
            info = await session.call_tool("get_database_info_tool", {
                "catalog": "paimon", "database": "csc"
            })
            print(info.content[0].text)

            # 执行查询
            result = await session.call_tool("execute_sql", {
                "sql": "select * from paimon.csc.ods_csc_log_audit limit 10"
            })
            print(result.content[0].text)

asyncio.run(main())
```

## 7. MCP 工具使用说明

### 7.1 `get_connection_status`

无参数。建议在执行 SQL 前先调用，确认 `connected: true`。

### 7.2 `get_database_info_tool`

按层级下钻，参数均可选：

| 传参 | 返回 |
|------|------|
| 无 | 可见 catalog 列表 |
| `catalog` | 该 catalog 下的 database |
| `catalog` + `database` | 该库下的 table |
| `catalog` + `database` + `table` | 列信息（内部表含建表语句） |

只传 `database` 时，catalog 默认为 `default_catalog`。

### 7.3 `execute_sql`

| 参数 | 必填 | 说明 |
|------|------|------|
| `sql` | 是 | 单条 SQL |
| `max_rows` | 否 | 客户端再截断返回行数（只能收紧） |
| `timeout_seconds` | 否 | 本次超时（只能收紧，不超过服务端上限） |

**成功返回**包含 `columns`、`rows`、`row_count`、`limit_applied`、`limit_source` 等。

**常见拒绝原因：**

| 场景 | 提示 |
|------|------|
| 只读用户执行 INSERT/UPDATE/DELETE | `SQL 未通过安全审计` |
| 任何用户执行 DROP/TRUNCATE 等 | `SQL 未通过安全审计` |
| 查询 scope 外的表 | `SQL 未通过安全审计` |
| 多语句 `;` 堆叠 | `SQL 未通过安全审计` |
| 数据库不可达 | `数据库未连接或当前不可用` |

**关于 LIMIT：**

- 没写 LIMIT **不会被拒绝**，服务端自动注入默认上限（配置项 `default_row_limit`，默认 1000）
- 写了过大的 LIMIT 会被收紧到 `max_row_limit`（默认 10000）
- 返回中 `limit_source` 为 `user` / `default_injected` / `capped`

完整字段说明见 [api.md](api.md)。

## 8. 运维

### 8.1 启动参数

```bash
python -m starrocks_mcp.main --help

# 常用
python -m starrocks_mcp.main --config config/settings.yaml --log-level INFO
python -m starrocks_mcp.main --config config/settings.yaml --host 0.0.0.0 --port 8080
```

也可使用脚本：

```bash
./scripts/start-local.sh          # 本地 Mock
./scripts/start-production.sh     # 生产（Linux）
```

### 8.2 健康检查

```bash
curl -s http://127.0.0.1:8080/healthz | jq
```

| 状态码 | 含义 |
|--------|------|
| 200 + `status: ok` | 服务正常，数据库可用（或 mock 模式） |
| 503 + `status: unavailable` | 真实驱动下数据库连不上 |

### 8.3 Prometheus 指标

```bash
curl -s http://127.0.0.1:8080/metrics | head -20
```

主要指标：

- `mcp_sql_requests_total` — 按 apikey、语句类型、状态计数
- `mcp_sql_duration_seconds` — 执行耗时
- `mcp_pool_in_use` — 连接池占用

### 8.4 审计日志

默认路径：`logs/audit.db`（可在 `settings.yaml` 的 `monitoring.audit_db_path` 修改）。

查询某用户最近调用：

```sql
SELECT ts, username, statement_type, sql_text, duration_ms, row_count, status, error
FROM request_log
WHERE username = 'alice'
ORDER BY id DESC
LIMIT 20;
```

## 9. 内网部署

离线包打包、安装、systemd 配置见 **[deploy-intranet.md](deploy-intranet.md)**。

简要步骤：

1. 解压 `starrocks-mcp-*-intranet-*.zip`
2. 运行 `scripts/install-offline.ps1`（Windows）或 `install-offline.sh`（Linux）
3. 复制并编辑 `config/settings.yaml`、`config/apikeys.yaml`
4. 设置密码环境变量后执行 `scripts/start-production.*`
5. 客户端将 MCP URL 改为内网地址：`http://<内网IP>:8080/mcp`

> Windows 打的离线包仅适用于 Windows + Python 3.11。Linux 需在目标环境重新执行 `scripts/package-intranet.sh` 打包。

## 10. 安全使用建议

1. **最小权限**：只读用户用 `role: read` + 尽量小的 `scope`。
2. **不要共享 apikey**：一人一 key，便于审计追责。
3. **双层防护**：服务端审计 + StarRocks 账号权限同时收紧。
4. **生产加 HTTPS**：在 Nginx 等反代后暴露 `/mcp`，`/metrics` 仅内网可达。
5. **定期轮换 apikey**：更新 `apikeys.yaml` 中的哈希后重启或等待热重载。
6. **关注审计日志**：对 `status=rejected` 的异常调用做告警。

## 11. 常见问题

### Cursor 显示未连接

- 确认本机服务已启动：`curl http://127.0.0.1:8080/healthz`
- URL 是否包含 `/mcp`
- `X-API-Key` 是否与 `apikeys.yaml` 中哈希对应的明文一致

### 返回 401 Unauthorized

- 未传 apikey，或明文 key 错误
- 使用了未在 `apikeys.yaml` 中配置的 key

### 查询被拒绝「安全审计」

- 只读 key 不能写操作
- 查询了 scope 外的 catalog/database
- 执行了 DDL 或多语句
- SQL 中只有表名、无法判断是否在 scope 内（fail-closed）

### 没写 LIMIT 会怎样？

**不会拒绝。** 服务端自动追加默认 LIMIT（1000 行），返回中 `limit_source` 为 `default_injected`。

### Mock 与真实库如何切换？

只改 `settings.yaml` 中的 `database.driver`：`mock` 或 `pymysql`，然后重启服务。

### 只有一个数据库账号怎么办？

`read_account` 和 `write_account` 可配置为同一用户；`readwrite` 写操作能否成功取决于该账号在 StarRocks 侧的权限。
